# 博客交流协会 · 导航站设计方案 v2

> 目标：把现在的「能用」版本，升级成**值得每天打开、愿意转发到微信群**的版本。
> 约束不变：纯静态、两个文件（`index.html` + `data/blogs.json`）、无后端、无打包工具。

调研方法：实际抓取并阅读了 14 个同类站点的 HTML/CSS（标注「实测」），其余为搜索摘要推断（标注「推断」）。

---

## 〇、已确认的三项决策（2026-09-15 拍板）

| # | 议题 | 决定 |
| --- | --- | --- |
| 1 | 配色 | **改为「暖白 + 墨绿 + 砖橙」**，替换 v1 的靛蓝三色渐变（规格见 3.5） |
| 2 | 技术栈字段 | **引入 `tech`**，作为与标签并列的第二个筛选维度（规格见 3.3、3.6） |
| 3 | 新鲜度维护 | **加 GitHub Action 每天抓 RSS 自动写回 `updated`**，接受仓库中出现 `.github/workflows/` |

由此带来的两个连带影响，实现时需注意：

- **约束放宽**：仓库不再严格是"两个文件"。但**运行时**依然只有 `index.html` + `data/blogs.json` 两个文件被浏览器加载——Action 与生成脚本只影响仓库结构，不影响站点。这一点要在 README 里写清楚，避免以后自己或贡献者困惑。
- **`blogs.json` 必须真的用起来 `tech`**：示例数据不能留空，否则筛选条会被自动隐藏，功能等于没做。示例数据应采用中文博客圈真实的生成器分布（Hexo / Typecho / Hugo / WordPress / Astro / Halo）。

## 一、同类站点调研

### 1.1 逐站要点

#### ① ooh.directory — https://ooh.directory （实测，2,433 个博客）

- **内容字段**：站名 → 一句话简介 → 「Updated 10 hours ago」 → 最新一篇文章标题 + 摘要 → 作者 → 字数 → 国家旗帜。详情页还有发文频率、首篇文章日期、posts-per-month 柱状图。
- **布局**：单列 `<ol>`，条目间仅 1px 顶边框，**每页 20 条**。不用卡片。
- **导航**：搜索 + 12 个分类（带计数 `Arts and media (932)`）+ 两个并列入口「Recently **added**」/「Recently **updated**」+ `/random/` 随机。
- **配色（实测自其 CSS 变量）**：

  | 变量 | 浅色 | 深色 |
  | --- | --- | --- |
  | 背景 | `#fff3f1` 暖粉白 | `#002e2c` |
  | 正文 | `#002e2c` 深墨绿 | `#ffdcd6` |
  | 标题 | `#e85c3b` 橙红 | — |
  | 链接 | `#8d3ea3` 紫 | `#bb7acd` |
  | 次要文字 | `#828e8d` | — |
  | 高亮选中 | `#0affed` 亮青 | — |

  字体是纯系统栈，标题 `font-weight:900`，栏宽上限 `100ch`，边框宽 3px。
- **最值得偷**：① **更新时间**是这类站点的核心竞争力，它把"死链列表"变成"活着的社区"；② 违反直觉但极和谐的配色——暖粉白底 + 墨绿正文 + 橙红标题，**文艺、有手作感，完全不像模板站**；③ 相对时间还带告警（`a month ago ⚠` 表示 feed 抓取失败）。

#### ② blogroll.org — https://blogroll.org （实测，1,293 个博客）

- **内容字段**：博客名（大号粗体）→ 一句话简介（常规字重灰色）→ 可选徽章。就这三样。
- **布局**：极简单列，靠留白分隔。
- **导航**：一行标签条 `Art & Design / Daily Life / ... / Recently Added` + `Submit your blog`。
- **亮点**：① 首屏一句**规模声明**「a humanly curated list of **1293** fine personal & independent blogs... **No algorithms ever!**」——瞬间建立可信度；② **策展徽章**（`Interview` 被访谈过、`Supporter` 赞助者），用元数据表达身份；③ 滚到第 100 条时插入一句轻量赞助请求，不打断浏览。

#### ③ 十年之约 — https://www.foreverblog.cn/blogs.html （实测）

- **内容字段**：只有两个可见字段——**站名 + 签约时间**。博主寄语被塞进 `<a title="...">` 当悬浮提示。
- **布局**：密集近似表格的纯文字条目，按**加入年份**分组（2017-2026 十个 tab）+「显示更多」。
- **亮点**：① 首页「履约数据」大数字：**1,901 履约中 / 756 已违约 / 4,772 未通过**——把社区健康度变成团体荣誉感；② **「异常名录」把死站单独隔离**，主列表永远保持"活的"；③ 寄语「十年说长不长，说短也不短」比任何简介都动人。
- **反面**：寄语藏在 `title` 里，**移动端没有 hover，基本看不到**。

#### ④ HeyBlog（原 zhblogs）— https://www.heyblog.net （实测，15,093 个博客）

- **内容字段**：站名 → 域名 → 简介 → 标签 chips → 「访问范围 全球可访问」→ 「信息更新时间 2026年9月3日更新」→「2026年9月加入」→ 订阅/站点地图/详情。
- **导航（同类最强）**：搜索 + **两级标签**（5 个主标签带计数 + 上百个子标签）+ **「技术组件」维度**（`Hexo 576 / WordPress 545 / Typecho 463 / Hugo 229 / Halo 88 / Jekyll 68 / Astro 22`）+ 访问范围 + **「长期不更」标签（39 个）**。
- **配色**：主色 `#0f7b80` 青绿系（hover `#0c666b`、深 `#0b5357`、浅底 `#d9eeef`），辅 `#f59e0b` 琥珀、`#34d399` 绿，中灰 `#64748b`。
- **最值得偷**：**「技术栈」作为筛选维度**——这是博客目录独有、比泛标签更有辨识度的切面，而且**纯静态数据就能实现**；「长期不更」标签优雅地处理了死站。
- **反面**：子标签一次铺开 200+ 个，视觉噪音极大（应折叠或按热度截断）。

#### ⑤ blogscroll — https://blogscroll.com （实测）

- **内容字段**：只有 16px favicon + 站名链接。**没有简介、没有作者、没有标签。**
- **布局**：32px 行高的超密列表，单屏可扫 40+ 条。
- **亮点**：「Surprise Me」随机按钮（5 行 JS）、分类标题带计数徽章 `71 Entries`、提供 RSS 与 **OPML 下载**。
- **反面（重要，务必避开）**：移动端 media query 里写死 `.category-container{width:600px;min-width:600px}`、字号 `3rem` → **在 360-414px 手机上必然横向溢出**；favicon 直接热链第三方站点，有隐私与混合内容风险；五年未更新，用的还是 `max-device-width` 时代的写法。

#### ⑥ blogs.hn — https://blogs.hn （实测）

- **布局**：`#index{column-count:auto; column-width:22rem; column-gap:3rem}` —— **用自动列宽做响应式，完全不需要 media query 栅格**。卡片是白底 + `border:2px solid #777` + **`border-bottom:6px solid #777` 的"厚底边"**，便宜又有质感。
- **窄屏策略**：`td:nth-child(1){display:none}` —— **逐列丢弃**，而不是横向滚动。
- **细节**：长域名用 `<wbr/>` 允许断行，不撑破卡片。深色模式全套变量替换（背景黑、文字 `#ddd`、卡片 `#222`、边框 `#333`）。字体 `ui-rounded` 圆润无衬线。

#### ⑦ diygod.cc/friends — https://diygod.cc/friends （实测，单页友链的最佳实现）

- **字段顺序**：64px 圆形头像 → 站名 → 箭头图标 → 一句话简介。
- **布局**：`grid-cols-1 sm:grid-cols-2`，卡片 `flex items-start gap-4 p-5 rounded-2xl`。
- **最值得偷的细节（纯 CSS，零 JS）**：卡片内叠了**两层绝对定位的虚线边框**——hover 时上层 `-translate-x-1 -translate-y-1`、下层 `translate-x-1 translate-y-1`，形成"双层虚线错位"的立体反馈；站名右侧箭头初始 `-rotate-45 translate-x-1 translate-y-1 opacity-0`，hover 归位淡入（"箭头飞入"）。**这是"看起来很贵"的最低成本手段**，6-8 行原生 CSS 就能还原。

#### ⑧ BlogFinder — https://bf.zzxworld.com （实测）

- **规模文案**：「与九百多位博友 成为近邻」。
- **简介质量极高**：「懒于当下，勤于长远。」「烟火烹百味，代码筑世界。」——证明 12-20 字中文简介能提供极高的扫视信息量。
- **「勤更不辍榜」** https://bf.zzxworld.com/s/diligent_list ：TOP 100，🥇🥈🥉 标前三，每条 = 站名 + 简介 + **最近 3 篇文章标题 + 日期**，同日期重复出现形成"刷屏感"= 勤奋的视觉证明。
- **可偷**：「勤更榜」**只靠比对 `updated` 字段排序就能算出来**，无后端也能做，而且比"浏览量榜"诚实得多。

#### ⑨ BlogsClub — https://www.blogsclub.org/members.html （实测，711 位博主）

- **排序维度**：按加入时间 / **随机排序** / 按浏览量 / 按内容主基调，并配解释文案「每次点击随机排序按钮都会重新打乱博客顺序，帮助您发现更多优秀博主」——**把随机当成"发现机制"来讲故事**。
- **「受限站点公示」**：被驳回/异常站点单独公示。
- **反面（关键）**：成员列表 HTML 里只有「Loading... 与服务器通信中...」——**完全依赖 API，静态托管无法复制**；导航塞了 15+ 个栏目，严重膨胀；`meta viewport` 写了 `user-scalable=no` 禁止缩放，可访问性差。

#### ⑩ 博友圈 — https://www.boyouquan.com （实测）

- **反面（关键）**：整站是 CSR SPA，首页与 `/blogs` 返回**完全相同的 2,467 字节空壳**（`<div id=app>` + 3 个 JS bundle）。无 JS 时页面全空，**对搜索引擎和链接预览完全不可见**。
- **可偷**：它 `noscript` 里内联的 PaperMod 深色 token 是**中文博客圈最被验证的深色配色**：`--theme:rgb(29,30,32)` / `--entry:rgb(46,46,51)` / `--primary:rgb(218,218,219)` / `--secondary:rgb(155,156,157)` / `--border:rgb(51,51,51)`。

#### ⑪ 开往 travellings — https://www.travellings.link （实测）

- **不是列表页，而是随机跳转机制**：进站就自动跳到一个随机成员站，**点浏览器「后退」会再次随机跳到另一个站**（Tips 文案：「↩️ 后退 网页可再次开往」）——**把随机探索变成可连击的交互，比"再来一次"按钮上瘾**。
- 成员表里带**「位置」字段**（徽标挂在成员站的顶栏/侧栏/底栏/中心，`*` 表示需滚动才可见）——很聪明的互惠凭证。

#### ⑫ indieblog.page — https://indieblog.page （实测）

- 首页只有一个 🎲 按钮。`/all` 列表用 Tabulator JS 渲染，服务端只输出「Sorry, this feature needs JavaScript」——**无 JS 完全不可用**（反面）。
- **可偷**：**提供完整 JSON 导出**（https://indieblog.page/export ，6,463 条）是目录站的信任状。你的 `data/blogs.json` 本身就是这个承诺，值得明说。

#### ⑬ 中文独立博客列表 — github.com/timqian/chinese-independent-blogs （实测，1,486 行）

- 呈现为一个 Markdown 表格，列顺序固定：`RSS feed | Introduction | Address | tags`（tags 用分号分隔）。
- **可偷**：这个**字段顺序**可以直接借用到 JSON；标签串在 JSON 里就是 `string[]`。
- **反面**：1,486 行纯表格，无搜索无分类，死链无人清理。

#### ⑭ Marginalia Search — https://search.marginalia.nu （实测）

- 首页文案极克制，只列 6 条价值主张：「Prioritizes non-commercial content」「Simple technology, no AI」「Privacy by default」「No data shared with 3rd parties」。
- 提供**纯文本浏览器专用界面**（`old-search.marginalia.nu`，"uses fewer modern CSS tricks"）——对移动优先站点是很好的姿态。

#### 抓取失败 / 已死的候选（不要参考）

`blogwebawards.com`（域名不存在）· `nav.iiilab.com`（404）· `blog.zhangqibot.com/links`（443 拒绝连接）· `chinese-independent-blogs.com`（域名不存在）· `icosahedron.website`（其实是个 Mastodon 实例）· `storeweb.cn`（1,260 字节 Vue 空壳）· `blogscroll.github.io`（301 到 blogscroll.com）

### 1.2 横向结论

**做得好的站点共有的 10 个特征**

1. **单列窄栏列表 + 1px 分隔线**，而非卡片墙——移动端最省空间、扫视最快。
2. **一句话简介是一等公民**，且有写作标准；缺失时给明确占位（HeyBlog：「该博客暂无简介」）。
3. **favicon 或头像作为视觉锚点**，二选一，不要中间态（blogscroll 16px 换 32px 行高；diygod 64px 圆头像换舒适两列）。
4. **计数徽章**：每个分类/标签旁标数字，让用户预判点击成本。
5. **两个时间入口并列**：「最近加入」与「最近更新」。
6. **随机发现是必备 CTA**——实现成本 5 行 JS，情感收益极高。
7. **多维度筛选面**：标签 + 一个"目录独有"维度（最优解是**技术栈**）。
8. **死站治理**：把失效博客隔离成「异常名录」/「长期不更」，而不是混在列表里。
9. **响应式靠"自动列数"或"逐列丢弃"**，绝不横向滚动。
10. **深色模式整套变量替换**，而非逐个元素改。

**必须避开的反面模式**

1. **无 JS 就没有内容**（博友圈、个站商店、indieblog.page/all）——对目录站是致命的：不可被搜索、分享无预览、弱网打不开。
2. **移动端固定像素宽度**（blogscroll 的 600px）→ 必然横向溢出。
3. **`user-scalable=no` 禁止缩放**（BlogsClub）→ 可访问性事故。
4. **关键信息塞进 hover-only 的 tooltip**（十年之约的寄语）→ 移动端看不到。
5. **一次性铺开上百个标签**（HeyBlog 子标签区）→ 应热度截断或折叠。
6. **栏目膨胀**（BlogsClub 15+ 栏目、BlogFinder 一屏 60+ 标题）→ 目录站的价值是"找到"，不是"逛遍"。
7. **只有名字没有简介**（chinese-independent-blogs、blogscroll）→ 扫视时无法决策。
8. **热链第三方 favicon**（blogscroll）→ 隐私、混合内容、性能三重风险。

## 二、对当前 v1 的自我诊断

已上线 v1 做对的：响应式三档、搜索防抖、标签频次排序、空状态、深色模式、XSS 转义、加载骨架屏。

对照调研，四个真实短板：

| # | 问题 | 依据 |
| --- | --- | --- |
| 1 | **卡片网格对同质化内容不合适**——3 列卡片墙的边框和色块把版面切碎，扫读效率低于列表 | ooh.directory、blogroll.org 都是列表 |
| 2 | **没有"活着的证据"**——读者无法判断哪个博客还在更新 | ooh.directory 的核心竞争力就是更新时间 |
| 3 | **标签全量平铺，数量增长后失效** | blogroll 用单行标签条、HeyBlog 用两级+计数 |
| 4 | **缺少规模声明与随机发现**，页面偏"工具感"，少了社群感 | blogroll 的规模声明、blogscroll 的 Surprise Me |

## 三、v2 设计方案

### 3.1 设计定位

一句话：**「一份会呼吸的群友博客清单」**——不是链接仓库，而是能看出"谁还在写、最近写了什么"的活目录。

三条原则：

1. **内容优先于容器**：弱化边框与色块，让博客名和简介成为视觉主体。
2. **密度可调**：列表（默认）与卡片（可选）双视图，记忆在 localStorage。
3. **诚实标示新鲜度**：宁可显示"3 个月前更新"，也不要假装一切活跃。

### 3.2 信息架构

```
┌─ Hero（手机上压缩到 ~170px，让首屏露出 2-3 个条目）
│  博客交流协会 · 收录独立博客，分享搭建经验
│  「已收录 12 个博客 · 其中 8 个近 30 天有更新 · 最近更新 2 天前」← 规模声明
├─ 工具栏（sticky）
│  [搜索框] [🎲 随机] [列表|网格]
│  [标签条：横向可滑 · 全部12 技术7 生活5 ... · 更多▾]
│  [排序：推荐 | 最近更新 | 最近加入 | 名称]
├─ 主体
│  ① 列表视图（默认）
│     ● 码农小站                       更新于 2 天前
│       一个前端工程师的独立博客，记录从零搭建的全过程
│       阿柴 · example.com · #技术 #前端
│  ② 卡片视图（可选，复用 v1 卡片 + diygod 双层虚线 hover）
├─ 空状态 / 无结果
├─ 「异常名录」折叠区（失联/长期不更的博客，默认收起）
└─ 评论区（Giscus）+ 页脚（提交入口 + 数据开放声明）
```

### 3.3 数据模型扩展

在**不破坏现有 5 个字段**的前提下向后兼容地扩展，全部可选，缺字段自动降级：

```jsonc
{
  // ===== v1 已有，保持不动 =====
  "name": "码农小站",
  "url": "https://example.com",
  "author": "阿柴",
  "description": "一个前端工程师的独立博客，记录从零搭建的全过程。",
  "tags": ["技术", "前端"],

  // ===== v2 新增，全部可选 =====
  "feed": "https://example.com/atom.xml",     // RSS/Atom，用于自动获取更新时间
  "tech": "Hexo",                             // 技术栈：Hexo/WordPress/Typecho/Hugo/Halo...
  "message": "写博客第五年，希望能一直写下去。",  // 「寄语」，来自十年之约的启发
  "added": "2026-03-01",                      // 加入协会时间 → 支撑「最近加入」
  "updated": "2026-09-10",                    // 最近更新，建议由 GitHub Action 自动填
  "status": "active",                         // active / dormant（长期不更）/ dead（失联）
  "avatar": "https://example.com/avatar.png"  // 可选头像
}
```

**字段取舍说明**

- `updated` + `feed` 是**投入产出比最高**的两个字段。有了 `updated`，「最近更新」排序、新鲜度圆点、勤更榜、月度活跃统计全部成立。
- `updated` **不要手工维护**——见第五节，用 GitHub Action 每天抓一次 RSS 自动写回。
- **`tech`（技术栈）是本方案最重要的一处差异化**。调研的 14 个站点里只有 HeyBlog 做了这个维度（Hexo 576 / WordPress 545 / Typecho 463…），而它对中文独立博客圈来说是最有辨识度的身份标签。**它是纯静态数据，不需要任何后端**。
- `message`（寄语）与 `description`（简介）不冲突：简介说"写什么"，寄语说"为什么写"。十年之约证明了寄语的感染力，但**不要学它塞进 `title` 属性**——移动端没有 hover。
- `avatar` 可选：有就显示，没有就用博客名首字母生成色块（色相由名称哈希决定，保证稳定）。**不要热链第三方 favicon**（blogscroll 的教训），跨域、隐私、失败率都不可控。
- `status` 支撑「异常名录」折叠区，把死站隔离出主列表。

### 3.4 列表视图的排版规格（核心改动）

参考 blogroll.org 的字重对比 + ooh.directory 的元数据密度：

| 元素 | 规格 | 理由 |
| --- | --- | --- |
| 博客名 | 17px（手机）/ 19px（桌面），`font-weight:700` | 扫读锚点，必须最重 |
| 新鲜度圆点 | 8px 圆点 + 12px 文字，紧贴标题右侧 | ≤30 天绿 / ≤180 天黄 / 更久或未知灰 |
| 简介 | 14px，最多 2 行（手机）/ 1 行（桌面） | 字号明显小于标题，形成层级 |
| 元信息行 | 12px：作者 · 域名 · 技术栈 · 标签 | 最低优先级 |
| 条目间距 | 内边距 16px + `border-bottom:1px solid`，**不用卡片边框** | 低噪音分隔，省高度 |
| 悬停（仅桌面） | 整行浅底 + 博客名变主色 + 箭头飞入 + 双层虚线错位 | 从 diygod.cc/friends 学来的纯 CSS 反馈 |

**移动端关键决策**：条目仍单列，但**博客名与简介必须完整可见**，不压缩到只剩标题——微信群用户是来"看有什么"的，不是来扫标题的。

### 3.5 配色方案（重要修正）

**放弃 v1 的靛蓝-紫-品红三色渐变。** 理由：调研显示最好的两个目录站（ooh.directory、blogroll.org）都走"文艺手作"路线，而渐变头部 + 彩色胶囊是**模板站的视觉签名**，会让人下意识觉得"这是个自动生成的导航站"。

改为**暖底 + 深墨绿正文 + 单一强调色**：

| 用途 | 浅色 | 深色 | 来源 |
| --- | --- | --- | --- |
| 页面背景 | `#fffaf7` 暖白 | `#1d1e20` | 暖白参考 ooh.directory；深色用 PaperMod token |
| 卡片/浮层 | `#ffffff` | `#2e2e33` | |
| 正文 | `#1f2d2b` 墨绿黑 | `#dadadb` | 参考 ooh.directory 的 `#002e2c` |
| 次要文字 | `#5c6b69` | `#9b9c9d` | |
| 弱化文字 | `#8a9694` | `#6b6c6d` | |
| 主色（标题/选中/链接） | `#c2410c` 砖橙 | `#fb923c` | 参考 ooh.directory 的橙红 `#e85c3b` |
| 边框/分割线 | `#e8e0da` | `#333333` | |
| 新鲜度绿 / 黄 / 灰 | `#15803d` / `#b45309` / `#a8a29e` | 同色提亮 | |
| 标签底色 | `#f4efea` 米灰 | `#3a3a40` | 仅选中态用主色 |

要点：

- **主色使用面积收敛到三处**：博客名悬停、选中标签、链接。标签默认是米灰底、灰字——**12 个彩色胶囊同时出现会压过博客名本身**。
- **头部改为低调的暖色块**（`#fffaf7` 或极浅的暖砂渐变），不再用高饱和三色渐变；高度在手机上从 ~280px 压到 ~170px。
- **一套 CSS 变量驱动深浅色**，而不是每个元素写两遍 `dark:` 类——这是 ooh.directory、blogs.hn、博友圈共同的做法，也让 body 更小。

### 3.6 标签与筛选系统升级

v1 是全量平铺按钮，v2 改为**单行横向可滑标签条**：

- 结构：`[全部 12] [技术 7] [生活 5] [前端 4] ...`，`overflow-x:auto` + `scroll-snap`，隐藏滚动条。
- 每个标签带计数；排序按频次降序（沿用 v1 逻辑）。
- **超过 12 个标签时**，第 13 位变成「更多 ▾」，点开弹出标签面板——避免标签条无限增长（HeyBlog 铺开 200+ 标签的教训）。
- 手机端**弃用下拉框**：触屏上横向滑动比下拉框更快、更直观，还省一行高度。
- **新增「技术栈」筛选条**（与标签条并列的第二行）：`[全部] [Hexo 5] [WordPress 4] [Typecho 3] [Hugo 2]`。数据缺失时整条自动隐藏。

### 3.7 三个"发现"功能

1. **🎲 随机逛逛**（参考 blogscroll 的 Surprise Me、ooh 的 /random/）
   工具栏一个骰子按钮，随机挑一个博客弹出轻量卡片（名称/简介/寄语 + 「去逛逛」）。**进阶玩法参考「开往」**：跳转后用 `location.replace` 让浏览器的「后退」变成"再随机一个"，形成可连击的探索体验。

2. **排序切换 + 「勤更榜」**（参考 ooh 的双入口 + BlogFinder 的勤更不辍榜）
   排序：`推荐（featured 优先）` / `最近更新` / `最近加入` / `名称`。
   另设一个「勤更榜」折叠区：按 `updated` 距离今天的天数排序，取前 10，🥇🥈🥉 标前三。**只需比对 JSON 里的日期，无后端也能算，且比"浏览量榜"诚实。**

3. **规模与活跃度声明 + 数据开放声明**
   Hero 一行小字：`已收录 12 个博客 · 其中 8 个近 30 天有更新 · 最近更新 2 天前`。
   页脚一句：`本站数据以 data/blogs.json 开放，欢迎自取`（参考 indieblog.page 的 JSON 导出、blogscroll 的 OPML）。这行字对"独立博客圈"受众有特殊的号召力。

### 3.8 移动端专项（最高优先级）

微信群是主要入口，且大多在微信内置浏览器打开：

- **头部压缩**：手机上 Hero 只留标题（24px）+ 一行简介 + 一行统计，让第一屏露出 2-3 个条目。
- **点击目标 ≥ 44px**：标签条、排序切换、骰子按钮的触控高度达标。
- **不用 `hover` 承载关键信息**：寄语、完整简介在触屏上通过「展开」呈现，不能只挂在 `title` 属性上（十年之约的教训）。
- **微信内置浏览器注意点**：避免复杂 `position:fixed`（键盘弹出易错位），用 `sticky`；避免 `100vh`（地址栏导致高度不准），用 `min-height:100svh` 并保留 `100vh` 兜底。
- **允许缩放**：`viewport` 不写 `user-scalable=no`（BlogsClub 的教训）。
- **分享卡片**：补 `og:title` / `og:description` / `og:image`，让链接在微信里显示成卡片而不是一串网址——这是"被转发率"的关键。
- **不横向溢出**：这是 blogscroll 最大的失败点，必须实测 360px 宽度下 `scrollWidth <= innerWidth`。

### 3.9 一个必须解决的技术债：noscript 兜底

调研中最刺眼的教训是：**博友圈、个站商店、indieblog.page/all 这些站，无 JS 时页面全空**，对搜索引擎、微信链接预览、弱网环境完全不可见。我们现在的 v1 也是这样——首屏是骨架屏，内容全靠 JS 渲染。

解决方案（仍然只有两个文件）：在 `#blog-grid` 里预置一份**静态渲染的博客列表 HTML**，JS 加载后用动态版本替换。这份 HTML 由一个小脚本从 `blogs.json` 生成并粘贴进 `index.html`。

代价：`blogs.json` 变更时需要重新生成这段 HTML（可以写成一个可选的 `tools/build-noscript.mjs`，或者手工维护）。
收益：SEO 可索引、微信预览有内容、弱网可读、关掉 JS 也能用。**对"被转发的目录站"来说这个收益很大。**

## 五、可选进阶：用 GitHub Actions 自动维护新鲜度

这是唯一需要"后端"的部分，但可以完全跑在 GitHub 上，不需要服务器：

```
每天 04:00 UTC 触发 GitHub Action
  → Node 脚本读取 data/blogs.json
  → 对每个 blog 的 feed 字段发起请求，取最新一篇的 pubDate
  → 写回 updated 字段（失败则保留原值，可标记 status: dormant）
  → 自动 commit & push
  → GitHub Pages 自动重新部署
```

收益：目录永远显示真实活跃度，零人工维护；顺带自动生成「勤更榜」和「本月更新过的博客」。
成本：约 40 行 Node 脚本 + 一个 workflow 文件（这会突破"只有两个文件"的约束，但只影响仓库结构，不影响运行时）。

### 分期实施建议

| 期 | 内容 | 改动范围 | 价值 |
| --- | --- | --- | --- |
| **P0** | 列表视图 + 标签横向滑动条 + 配色改版 + 头部压缩 + og 分享卡片 + 移动端实测 | 只改 `index.html` | 解决四个短板中的三个，手机体验提升最明显 |
| **P1** | 数据模型扩展（`tech`/`feed`/`added`/`updated`/`message`/`status`）+ 新鲜度圆点 + 技术栈筛选 + 规模声明 | `index.html` + `blogs.json` | 让站点"看起来是活的"，并做出差异化 |
| **P2** | 随机逛逛 + 勤更榜 + 排序切换 + 异常名录 + noscript 兜底 | `index.html` + 生成脚本 | 发现感、可访问性、SEO |
| **P3** | GitHub Action 自动更新 `updated` | 新增 workflow + 脚本 | 一劳永逸的自动化 |

**建议先做 P0**：纯前端改动，风险最低，却直接改善微信群里的第一印象。
